# TRACE data package

A boundary-defined export of seven frozen QSAEC evaluation panels, together with
the minimum source audio and a script that rebuilds every panel waveform
bit-for-bit from the frozen manifests.

Nothing in this package was regenerated by re-running a model. The manifests are
the frozen artefacts; only host absolute paths were removed.

## Layout

```
data/
  manifests/            one frozen manifest per panel, plus FROZEN.json
    baseline.jsonl
    global_rms.jsonl
    repair.jsonl
    subst.jsonl
    absent.jsonl
    prompt.jsonl
    fixed.jsonl
    FROZEN.json         per-panel source path, source sha256, counts, provenance hashes
  audio_sources/
    stems/<tuple_id>/subset_{001,010,100}.wav   192 files
    substitutions/<audit_id>.wav                160 files
    fixed/<tuple_id>/<view>.wav                 256 files
    INDEX.jsonl                                  sha256 + ESC-50 attribution for all 608
  design/
    repair_design.jsonl  rid -> target / distractor tuples for the repair panel
    subst_design.jsonl   rid -> substitute clip, rms_scale, original target stem
  ESC50-LICENSE.txt      ESC-50-master/LICENSE, extracted verbatim from the archive
  ESC50-meta.csv         ESC-50-master/meta/esc50.csv, extracted verbatim
  source_provenance.json archive identity, licence terms, attribution chain
scripts/
  render_audio.py        rebuild frozen audio from manifests + audio_sources
```

## Manifest schema

Each line is one scoring condition. Rows keep the frozen `condition_id`,
`source_tuple_id`, `question_id`, `question`, `y_present`/`y_absent`,
`target_index`, `target_category`, `snr_db`, `overlap`, `distractor_count`,
`distractor_replicate`, `included_indices`, `target_gain`, `distractor_gain`,
`energy_variant` and, where the panel defines them, the prompt and annotation
metadata (`prompt_template`, `label_mapping`, `semantic_answer_present`,
`absent_category`, `absence_policy`, `annotation_audit`, `selection_seed`,
`audit_status`, `verification_basis`).

`views` keeps each frozen view verbatim: `intervention`, `removed_index`,
`audio` (output-relative path), `audio_sha256`, `energy_variant`,
`intervention_semantics`, and the recorded `pre_rms`, `post_rms`, `pre_peak`,
`post_peak`, `normalization_gain`, `shared_safety_gain`, `surrogate_seed`.

Two field families were rewritten so that the package carries no host paths:

* `source_audio` / `source_audio_sha256` list package-relative stem references
  (`audio_sources/stems/<tuple_id>/subset_010.wav`), resolvable against the data
  root and identical to the `ref` values in `audio_sources/INDEX.jsonl`. The hash
  values are the frozen ones.
* `subst_target_audio` becomes `audio_sources/substitutions/<audit_id>.wav`,
  keeping the frozen `subst_target_sha256`. `rms_scale` and `design_peak` are
  joined in from `design/subst_design.jsonl` so the substitution is reproducible
  from this package alone.
* `source_audio_metadata[*].source_audio` in `fixed`/`prompt` becomes a symbolic
  `audit:<root>/<clip>.wav` reference plus `source_audit_id`, because the audited
  crop pool itself is not redistributed. `source_audio_sha256`, `source_frames`,
  `source_rms_before`, `source_rms_after` and `source_scale` are preserved.

`repair` rows additionally carry `repair_role_index`, `repair_index`,
`repair_target`, `repair_distractors`, `repair_distractor_categories` and
`repair_target_tuple_id`, which reconnect the `esc50r_*` condition ids to the
original ESC-50 tuples for analysis.

## Source audio

`audio_sources/INDEX.jsonl` has one entry per bundled clip:

* `stems` — the three single-constituent crops of each tuple, stored with
  `common_constituent_gain` already applied. `render_audio.py` divides that gain
  back out and takes the 2.0 s centre crop, matching the frozen renderer.
  `esc50_filename`, `esc50_category` and `esc50_fold` give ESC-50 attribution,
  and each filename was checked against the archive's own `audio/` inventory.
* `substitutions` — one clip per substitution design row, with `rms_scale`,
  `audit_id`, `audit_root` and `esc50_filename`.
* `fixed` — the frozen query-swap mixture views. The three query roles of a tuple
  are byte-identical, so one file per `(tuple, view name)` serves the `fixed`,
  `prompt` and `absent` panels.

No model weights, no ESC-50 archive, and no full pre-rendered view tree are
included.

## Rebuilding audio

```bash
# smoke test: first 4 conditions of every panel, nothing written
python3 scripts/render_audio.py --check-only --limit 4

# hash-verify a whole panel in memory
python3 scripts/render_audio.py --check-only --panel baseline

# render one panel to disk
python3 scripts/render_audio.py --panel subst --output-dir /path/to/out

# render everything (each panel gets its own subdirectory)
python3 scripts/render_audio.py --output-dir /path/to/out

# re-verify an output tree in place instead of re-rendering it
python3 scripts/render_audio.py --output-dir /path/to/out --verify-existing
```

`--panel` accepts `baseline`, `global_rms`, `repair`, `subst`, `absent`, `prompt`
and `fixed`, and can be repeated. `--condition-id` (repeatable) selects individual
conditions and is the hook used for factor-coverage sampling.

Every generated view is checked against the frozen `audio_sha256`; the run aborts
on the first mismatch. A non-empty panel directory is never overwritten — the
tool exits with an error unless `--verify-existing` is passed.

The output is directly scorable, because `run_stress.py` resolves a view as
`manifest.parent / view["audio"]`:

```
<output-dir>/<panel>/stress_manifest.jsonl
<output-dir>/<panel>/FROZEN.json
<output-dir>/<panel>/<view audio>
```

`fixed`, `prompt` and `absent` reuse the frozen views instead of re-deriving
them, and their view paths are deduplicated per `(tuple, view file)`, so a prompt
render stores 256 files rather than 6144 identical copies.

Panels must be rendered into separate directories because `baseline` and
`global_rms` share condition ids; the tool always creates one subdirectory per
panel for you.

## Verification status

Every panel was hash-checked in full, in memory, against the frozen
`audio_sha256` values:

| panel | conditions | views verified |
|---|---|---|
| `baseline` | 3456 | 11520 / 11520 |
| `global_rms` | 3456 | 11520 / 11520 |
| `repair` | 2880 | 11520 / 11520 |
| `subst` | 2880 | 9600 / 9600 |
| `absent` | 512 | 512 / 512 |
| `prompt` | 1536 | 6144 / 6144 |
| `fixed` | 192 | 768 / 768 |

51584 / 51584 views reproduced bit-for-bit. Before the full runs, each panel was
also probed with a greedy condition sampler that covers every value of every
factor (SNR, overlap, distractor count and replicate, target index, answer
parity, prompt template, label mapping, repair index and role, substitution clip
and category) with no uncovered factor/value pair.

Separately checked: no view path in any exported manifest is absolute or escapes
its manifest directory; every source reference resolves inside the package;
`baseline` and `global_rms` have identical condition ids and identical
`full`-view hashes; a full `fixed` render produces 768 verified views as 256
deduplicated files; re-rendering into a non-empty directory is refused; and
`--verify-existing` re-verifies it in place.

`manifests/FROZEN.json` records, for every panel, the sha256 of the source
manifest it was exported from, a sanitized source-path provenance label, and the sha256
of each accompanying frozen sidecar, so the export can be traced back.

## Known limitations

* **The original blind listening annotations are not included.** Completed per-clip response sheets and numeric confidence values were not recovered. Standalone listener attestations were not copied. The absent manifest does retain annotation-level audit fields derived from source labels and superclass disjointness; its historical `audit_status: verified` is not a released record of independent listening. These fields do not replace raw listener records. The audit *mapping* is included only
  because attribution requires it: `source_audit_id` in the `fixed`/`prompt`
  rows and `audit_id` in `INDEX.jsonl` reveal which recording a clip came from.
  Do not show that mapping to annotators if the panel is ever re-annotated blind.
* **The `absent` panel is the annotation-disjoint revision.** The exported manifest is the
  annotation-disjoint revision (`absent_manifest_annotation_disjoint_v1.jsonl`,
  `audit_status: verified`). The earlier candidate carried
  `ready_for_inference: false` and 0 audit-verified tuples; its hash and the hash
  of `ABSENT_FROZEN.json` are recorded in `manifests/FROZEN.json` for comparison.
* **`phase_scrambled` is out of scope.** The source project also includes a phase-scrambled
  energy variant; it is not one of these seven panels and is not included.
* **`fixed`, `prompt` and `absent` are reused, not re-derived.** Their views are
  shipped as frozen bytes. `render_audio.py` verifies them but does not
  reimplement the query-swap renderer, which uses a different gain and
  normalisation pipeline from `render_stress.py`.
* **`global_rms` reuses the recorded gains.** The renderer applies the
  `normalization_gain` and `shared_safety_gain` stored in each frozen view rather
  than recomputing them, which is what makes the rebuild bit-exact.
* **The upstream URL was not re-resolved over the network.** The repository URL
  and DOI in `source_provenance.json` are quoted from the header of the archive's
  own `LICENSE`; the archive is identified by its sha256 and internal inventory.
* **This is a data package, not a reproduction of the paper's results.** This audio subsection alone does not reproduce statistics. The repository now also includes `data/scores/` and the separate `analysis/` pipeline; no model was rerun during packaging.
